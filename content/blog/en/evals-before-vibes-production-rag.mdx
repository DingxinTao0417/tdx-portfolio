Every RAG system I've deployed has gone through the same arc: a thrilling first demo, a quiet period of "it's pretty good," and then a slow erosion of trust as users hit edge cases nobody measured. The fix isn't a better model. It's a harness that tells you the truth before your users do.

## The golden set is the product

Start with 50 to 300 real questions and reference answers, written *with* the people who will use the system. Store them next to the code, version them, and treat a change to the golden set with the same seriousness as a schema migration.

```python title="golden.py"
from pydantic import BaseModel

class GoldenCase(BaseModel):
    id: str
    question: str
    reference_answer: str
    must_cite: list[str]          # document ids that a faithful answer needs
    forbidden_scopes: list[str]   # ACL scopes the asker is NOT allowed to see
    tags: list[str] = []
```

Notice `forbidden_scopes`. Permission leaks are a correctness failure, not a security afterthought, so they live in the same test set.

## Three metrics that predict trust

I've tracked a dozen metrics across deployments. Three of them consistently correlate with whether users keep coming back.

### Faithfulness

Is every claim in the answer supported by the retrieved context? Scored by a grader model with a strict rubric, calibrated monthly against human labels on a 10% sample.

### Citation precision

Of the citations shown, how many actually support the sentence they're attached to? Users forgive a missing citation; they do not forgive a wrong one.

### Answer latency at p95

Not p50. The slow tail is what people remember, and it's usually caused by re-ranking too many candidates or a cold model.

## Running it nightly (and on every PR)

```yaml title=".github/workflows/evals.yml"
on:
  pull_request:
    paths: ["prompts/**", "retriever/**", "golden/**"]
  schedule:
    - cron: "0 6 * * *"

jobs:
  evals:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: uv run python -m evals.run --golden golden/ --report report.json
      - run: uv run python -m evals.gate --report report.json --min-faithfulness 0.9
```

The `gate` step fails the PR if faithfulness drops below the threshold. That single check has blocked more regressions than any code review.

## The dashboard nobody looks at (until they need to)

Faithfulness, citation precision, p95 latency, cost per answer — one chart each, one page, no filters. When a number moves, the page also shows the diff of the prompt or retriever config that shipped in the same window. Boring dashboards get trusted.

## What changes when you have this

- You stop arguing about prompts and start comparing numbers.
- Model upgrades become a Tuesday, not a project.
- Your customer's security team gets a report instead of a promise.

Vibes are a fine way to start. They're a terrible way to operate.
