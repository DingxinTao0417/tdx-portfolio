# 方案画布与利益相关者

## 学完能做什么

你能用一页方案画布对齐业务、技术和安全责任，并明确哪些决定需要谁确认。

## 核心概念

方案画布是协作材料，不是详细设计的替代品。它包含问题与现状、用户和任务、一期范围、资料与接口、指标和验收、风险与限制、责任人及待确认项。每项应能追溯到访谈或测量证据；未知项不要写成既定事实。

利益相关者不只包括付款或提需求的人。实际使用者、流程负责人、资料维护者、接口维护者及安全审查者都可能影响交付。明确谁提出意见、谁执行、谁有权批准，避免将一次讨论当成所有人的授权。

## 情境拆解

虚构企业的运营负责人希望快速建单，主管担心缺少设备编号，接口维护者关心重复请求，安全角色要求门店隔离。画布可以将这些诉求分别变成字段校验、幂等处理与权限测试，并标明负责人。

若运营负责人同意演示，但安全角色尚未确认数据边界，就只能继续使用合成资料与 mock API；不能把业务认可解释成真实数据接入许可。

## 常见误区

画布写满功能名却没有完成标准，无法支撑决策。另一个误区是把所有人都列为负责人，实际出现问题时却无人处理。

## 画布应该记录决定与未知项

一页方案可以把访谈、基线和范围连接起来。它不需要把未知信息包装成完整答案。例如“制度维护者待确认”比随意写一个负责人更有用，因为它明确了项目的依赖。

模拟业务方要求立刻自动审批，技术方只提供只读接口。这是范围冲突，需要决定是否缩小一期目标，不是换一个提示词就能解决。

## 动手：合并前面三课的产物

1. 把任务、现状、一期范围、验证方法和依赖写进同一张方案画布。
2. 对资料、身份、接口、验收和变更，分别写执行者与决策者。角色名称仅用于教学分工。
3. 加入一个冲突：客户希望的动作超过现有接口或权限。写出选项、代价和待确认决定。
4. 检查画布与验收例子是否一致，不让后续图表悄悄扩大一期范围。

~~~text
用户与任务：
现状与证据：
一期范围 / 不做清单：
方案与系统依赖：
验收样本及通过条件：
资料、接口和验收责任：
当前冲突与可选处理：
待确认项 / 下一次检查：
~~~

### 检查产物

把画布交给另一位开发者，他能指出可以开始的部分，以及还不能承诺的部分。模块案例会检查整套方案的一致性，不只检查栏目有没有填满。
